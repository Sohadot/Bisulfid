# Bisulfid Visual Engine Roadmap

**Date:** 2026-05-31  
**Status:** Staged governed visual engine plan

## Stage 1: Design-system foundation (6N-A) — Complete

Internal tokens, components, SVG assets, motion governor. Zero external dependencies.

## Stage 2: Template integration (6N-B) — Pilot complete

Wire tokens/components into publication frames. Controlled integration sample validates rendering before corpus-wide refresh.

## Stage 3: Missing-E motion layer

Governed CSS/motion-governor.js animation for the Bisulfide/Bisulfid spelling boundary. Requires `prefers-reduced-motion` compliance and no JS-required content.

## Stage 4: Term-node visual identity

Inline term-node glyphs, relation-lattice data binding, ontology-aware styling at scale.

## Stage 5: Source-crystal authority state

Full crystal state machine UI (required → candidate → verified → approved) bound strictly to registry truth — never default-approved.

## Stage 6: Language-depth coordinate system

Multilingual layer visualization (EN/DE active; AR/FR/ES/JA/ZH reserved) with RTL readiness.

## Stage 7: Relation-lattice system

Structured term relationship graphs with governed data sources only.

## Stage 8: Raw WebGL chemical-space prototype

Experimental spatial chemical-language visualization. **Governed sprint required.** No external 3D libraries.

## Stage 9: Raw WebXR / AR experimental layer

Experimental immersive layer. **Governed sprint required.** Not indexation-blocking until explicitly authorized.

## Why each stage must be governed

Each stage affects public presentation, source/claim perception, and indexation readiness. Staged validation prevents premature search exposure of immature visuals.

## Why no external UI/3D libraries

Sovereign control, zero supply-chain risk, 14,000–100,000+ page static scale, and strict source/claim boundary enforcement require dependency-free presentation.
